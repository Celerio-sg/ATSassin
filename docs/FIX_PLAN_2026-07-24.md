# ATSassin UAT Fix Sprint — Implementation Plan

## Context

UAT executed 2026-07-24 (full findings: `docs/UAT_REPORT_2026-07-24.md`) scored the build 2.375/5.0 vs a 4.2 target — verdict **Needs Fixes**. Role inference and evaluation quality are strong, but the advertised discover→evaluate→track→tailor chain is structurally broken: pipeline subcommands are dead code, jobs are never persisted so tailoring feeds the candidate's own profile back in as the "job description", `evaluate --file` crashes on non-UTF-8 input (including the repo's own fixture), and `scan` presents fabricated-looking board results. This plan fixes all Critical/High issues plus the parser and cosmetic bugs, reworks scan to do real scraping (user's explicit choice over minimal honesty-labeling), adds CLI-level tests to close the coverage gap that let these ship, and reconciles docs/setup with actual behavior.

**Executor note:** this plan is written for a smaller model. Follow steps in order (they're dependency-ordered). Exact code is given where precision matters — use it as written unless it fails to compile, in which case fix minimally. Root causes are already verified; do not re-investigate.

**Key files:** `src/cli.rs`, `src/pipeline/tracker.rs`, `src/engine/profile_parser.rs`, `src/pipeline/scraper.rs`, `src/models/job.rs`, new `tests/cli.rs`.

**Verified facts you can rely on:**
- `PipelineTracker::add_pipeline_entry(job_id, status)` and `update_pipeline_status(entry_id, status)` exist and work (`src/pipeline/tracker.rs:181,211`). `save_job` exists (`:133`) but is never called. There is NO `get_job` — it must be added.
- Pipeline `status` is stored JSON-quoted (literally `"new"` with quotes) via `serde_json::to_string`. New code must match this format; do not "fix" it.
- `PipelineStatus` derives `Clone`; variants: New, Evaluated, Drafted, Exported, Applied, Interviewing, Offered, Rejected, Archived (serde lowercase).
- `tests/uat/scenario_1_simon_brender/profile.md` contains **16** `Experience:` headers.
- `tests/fixtures/sample_jd.txt` is UTF-16LE with BOM (FF FE).
- `assert_cmd`, `predicates`, `tempfile` are already dev-dependencies. `csv`, `regex`, `scraper`, `serde_json` are already dependencies. Add no new dependencies.

## Step 1 — Encoding-tolerant file reader (fixes UTF-8 crash, Issue #3/#15)

**`src/engine/profile_parser.rs`** — add two public module-level functions (below the `use` statements):

```rust
/// Read a text file tolerating UTF-8, UTF-16LE, and UTF-16BE (BOM-detected).
pub fn read_text_lossy(path: &Path) -> Result<String> {
    let bytes = fs::read(path).with_context(|| format!("Failed to read file: {}", path.display()))?;
    Ok(decode_text_lossy(&bytes))
}

pub fn decode_text_lossy(bytes: &[u8]) -> String {
    if bytes.len() >= 2 && bytes[0] == 0xFF && bytes[1] == 0xFE {
        let units: Vec<u16> = bytes[2..].chunks_exact(2)
            .map(|c| u16::from_le_bytes([c[0], c[1]])).collect();
        String::from_utf16_lossy(&units)
    } else if bytes.len() >= 2 && bytes[0] == 0xFE && bytes[1] == 0xFF {
        let units: Vec<u16> = bytes[2..].chunks_exact(2)
            .map(|c| u16::from_be_bytes([c[0], c[1]])).collect();
        String::from_utf16_lossy(&units)
    } else {
        let bytes = bytes.strip_prefix(&[0xEF, 0xBB, 0xBF]).unwrap_or(bytes);
        String::from_utf8_lossy(bytes).into_owned()
    }
}
```

Change `parse_markdown` (line ~43) to use `read_text_lossy(path)` instead of `fs::read_to_string(path)`.

**Fixtures:** copy `tests/fixtures/sample_jd.txt` byte-for-byte to `tests/fixtures/sample_jd_utf16.txt` (keep UTF-16LE — regression test needs it), then re-save `tests/fixtures/sample_jd.txt` as UTF-8.

impl PipelineStatus {
    pub fn parse(s: &str) -> anyhow::Result<Self> {
        match s.trim().to_lowercase().as_str() {
            "new" => Ok(Self::New),
            "evaluated" => Ok(Self::Evaluated),
            "drafted" => Ok(Self::Drafted),
            "exported" => Ok(Self::Exported),
            "applied" => Ok(Self::Applied),
            "interviewing" => Ok(Self::Interviewing),
            "offered" => Ok(Self::Offered),
            "rejected" => Ok(Self::Rejected),
            "archived" => Ok(Self::Archived),
            other => anyhow::bail!("Invalid status '{}'. Valid statuses: new, evaluated, drafted, exported, applied, interviewing, offered, rejected, archived", other),
        }
    }
}

## Step 3 — Wire pipeline subcommands (Issue #1, Critical)

**`src/cli.rs`** — replace `handle_pipeline` (~line 491, currently ignores `_args` and always lists) with a full `match &args.action`:

- `List`: current behavior (update the empty-pipeline hint to mention `evaluate --file`).
- `Add { job_id, status }`: parse status via `PipelineStatus::parse` (default `New` if omitted); if `tracker.get_job(job_id)?` is `None`, print a warning that no job record exists but add anyway; call `tracker.add_pipeline_entry`; print the entry id and status.

## Step 6 — Scan: real per-board scraping rework (Issue #4) — USER-CHOSEN SCOPE

Replace the current fabricated-results behavior in `src/pipeline/scraper.rs` with real scraping where feasible and **honest failure** where not. Design per board:

**6a. LinkedIn — use the public guest API (no auth needed):**
- Search: `GET https://www.linkedin.com/jobs-guest/jobs/api/seeMoreJobPostings/search?keywords={query}&start=0` with a realistic browser User-Agent. Returns an HTML fragment of `<li>` job cards.
- Parse each card with the `scraper` crate: title from `h3.base-search-card__title`, company from `h4.base-search-card__subtitle a` (fallback: `h4.base-search-card__subtitle`), location from `span.job-search-card__location`, **per-job URL from `a.base-card__full-link[href]`** (strip query params after `?`). Job id: extract the numeric id from the URL (`-(\d+)$` on the path, or `data-entity-urn` attribute `urn:li:jobPosting:(\d+)`).
- Description fetch (best-effort, rate-limited by existing `self.rate_limit_ms` sleep between requests): `GET https://www.linkedin.com/jobs-guest/jobs/api/jobPosting/{id}`, parse `div.show-more-less-html__markup` text. On failure, leave description as the card snippet — do not fail the scan.
- Extend `JobSummary` with `pub description: Option<String>` (update all construction sites; `None` where unavailable).

**6b. Seek — use the SPA's JSON search API:**
- `GET https://www.seek.com.au/api/chalice-search/v4/search?siteKey=AU-Main&keywords={query}&pageSize={limit}` with browser User-Agent and `Accept: application/json`.
- Parse JSON: `data` array; per item: `title`, `advertiser.description` (company name), `location` + `area` (join non-empty with ", "), per-job URL `https://www.seek.com.au/job/{id}`, description from `teaser` field.
- If the response is not valid JSON or `data` is missing (API may have changed), return `Ok(vec![])` and log a debug message — the honest-failure path below handles it.

**6c. Indeed and Glassdoor — honest attempt-then-fail:**
Both are Cloudflare-protected; plain reqwest scraping does not work. Keep the existing HTTP attempt (it costs one request), but on 0 results do **not** silently substitute social results labeled as the board. Instead print to stderr: `warning: '{board}' blocked automated access — no results. Use `--boards linkedin,seek,social` or open {search_url} manually.` and return the empty result. The existing headless/fantoccini fallback may remain in the chain (it's a no-op unless a WebDriver/MCP browser is running), but its results must use company "Unknown" instead of "Headless WebDriver Company" and location "Unknown".

**6d. `scrape_board` orchestration changes:**
- Remove the automatic `scrape_social` fallback for named boards entirely. `"social"` remains a first-class board choice; add it to the default board list in `src/config.rs` `ScrapingConfig::default()` (`boards: ["linkedin", "seek", "social"]` — drop indeed/glassdoor from defaults since they can't be scraped; they remain usable via `--boards`).
- Do not `bail!` when one board returns 0 — return an empty `ScrapeResult` so other boards still print (the current per-board loop in `handle_scan` propagates errors with `?`, killing remaining boards).
- Delete all hardcoded fake company/location strings ("LinkedIn Recruiter / Hiring Manager", "SEEK Employer", "Indeed Employer", "Glassdoor Employer", "APAC / Remote", etc.). Real values or "Unknown" only.

**6e. `handle_scan` in `src/cli.rs`:**
- After scraping each board, **persist real jobs**: for each `JobSummary` with a non-empty per-job URL (not a search-page URL), build a `models::job::Job` (id: `uuid::Uuid::new_v4()`, description: `summary.description.unwrap_or(summary.snippet)`, source: board name) and call `tracker.save_job` (construct a `PipelineTracker` at the top of the function). Print each job's short id so the user can `evaluate --job-id` / `tailor --job-id` directly: `  - {title} at {company} ({location})\n    id: {id}\n    URL: {url}`.
- Print the board's result count as `[{board}] Found {n} jobs` and, when n == 0, nothing further (the scraper already printed the stderr warning).

**Risk note for executor:** the LinkedIn guest API and Seek JSON API are undocumented and can change or rate-limit. Code defensively: any parse failure → `Ok(vec![])` + debug log, never a panic. Do not write network-dependent unit tests for these; verification is manual (Step 9).

## Known non-goals / risks

- `extract_location` still mis-picks the headline line (pre-existing, out of scope — noted for next sprint).
- Duplicate `pipeline add` for the same job id creates multiple rows (no uniqueness constraint) — kept as-is to stay surgical.
- LinkedIn guest API / Seek JSON API are undocumented; if either has changed, the scraper must degrade to the honest empty-result warning, never fabricate. Manual verification required; no network tests in CI.
- Lightning AI 401 (Issue #12) is NOT addressed here — needs a known-good credential to diagnose first.
- `evaluate --job-id` semantics change: old databases with pipeline entries but no jobs rows now get "Job not found in database" — intended, since no real description ever existed for those.
- **Employer reviews/ratings and referral-network recommendations — explicitly out of scope, not fabricable.** Requested in a later UAT/gap-analysis pass (2026-07-24, post-TUI-rebuild). No honest free data source exists: Glassdoor/Indeed employer-review pages are already confirmed bot-protected (same block that `scan --boards glassdoor/indeed` hits), and a "referral network" implies a social graph of the user's own contacts that the tool has no access to. Building either would mean either scraping a site that will block us the same way, or inventing plausible-looking numbers — the exact defect class this fix sprint exists to remove. To do this honestly in a future sprint: (a) ratings — integrate a paid/licensed employer-review API (e.g. Glassdoor's official partner API) as a strictly optional, clearly-labeled data source, never a default; (b) referrals — add a user-supplied contacts field (the user pastes in their own known contacts/notes) so the data source is the user, not a scrape or invention.
