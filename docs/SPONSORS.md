# Sponsorship strategy for ATSassin

This guide turns the maintainer's GitHub Sponsors page from a bare button into a transparent, low-friction way for users and companies to fund the project’s sustainability.

## Why sponsors matter here

ATSassin is building a **free, autonomous earning optimizer for everyone**. That means:

- No paid tiers that lock features behind a subscription.
- No selling user data to cover server costs.
- No venture capital that would eventually demand a return.

Sponsorship is the cleanest way to keep the project independent, the core tool free, and the maintainers fed. Sponsors are not buying a product; they are investing in a public good.

## GitHub Sponsors profile checklist

GitHub Sponsors profiles live in the GitHub UI, not in this repo, but the content below should be copy-pasted into the sponsor dashboard.

### Profile picture / avatar

Use the project avatar if one exists, or a clean headshot of the maintainer. A face builds trust; a logo builds brand. For a personal creator account, a friendly headshot usually outperforms a logo.

### Short bio / tagline (160 characters)

> "Building ATSassin — a free, local-first, privacy-first job-search assistant that helps anyone land better work without selling their data."

### Full profile story

Start with impact, then the ask, then the use-of-funds. Example:

> ATSassin is a local-first, open-source job-search assistant that infers roles, researches markets, tailors resumes, and tracks applications — all on your own machine, with no data sold and no SaaS required.
>
> Your sponsorship keeps the core tool free and independent. Funds cover CI minutes, hardware for low-spec testing, release automation, documentation, and the time needed to review PRs and guide new contributors.
>
> Sponsors are thanked publicly in release notes and are welcome to a private Discord channel for roadmap previews.

### Profile goals

Set 2–3 public goals with real numbers. Vague goals convert poorly.

| Goal | Amount | Why it matters |
|---|---|---|
| **Keep CI green** | $500 / month | Covers GitHub Actions minutes, test hardware, and release builds. |
| **Fund maintenance hours** | $1,000 / month | One day per week of dedicated review, triage, and mentorship. |
| **Sustain full-time development** | $8,000 / month | Maintainer can reduce client work and focus on ATSassin. |

Update goals as they are hit. Nothing kills momentum like a stale funding goal.

## Recommended tier structure

Keep tiers simple: one low-friction entry tier, one enthusiast tier, one company tier.

| Tier | Monthly | Name | Perks (must be allowed by GitHub Sponsors ToS) |
|---|---|---|---|
| **Supporter** | $5 | “Coffee” | Name in `SPONSORS.md` + release-notes thank-you. |
| **Contributor** | $25 | “Advocate” | Above + sponsor-only Discord role + early access to releases. |
| **Sustainer** | $100 | “Champion” | Above + logo/link in `SPONSORS.md` + quarterly roadmap call. |
| **Organization** | $500+ | “Partner” | Above + public thank-you in README + input on quarterly priorities. |

### What to offer (allowed)

- Public thank-you in `README.md`, `SPONSORS.md`, and release notes.
- A sponsor-only Discord role and channel.
- Early access to releases, betas, and roadmap previews.
- Priority support in GitHub Discussions or Discord.
- Input on roadmap priorities (not control, input).
- Company logo and link in a supporters section.

### What to avoid (not allowed or risky)

- **No paywalled code or exclusive features.** The open-source project must remain fully open.
- **No equity, tokens, or investment returns.** GitHub Sponsors is not a crowdfunding platform.
- **No guaranteed outcomes** (e.g., “we will merge your feature”).
- **No personal data or consulting in exchange for sponsorship.** Keep it clean.

## Funnel in the repository

1. **README badge**: add a GitHub Sponsors badge near the top.
2. **README section**: a short “Support ATSassin” paragraph near the bottom, before the License section.
3. **This file (`docs/SPONSORS.md`)**: lists current sponsors, explains tiers, and links to the sponsor page.
4. **Release notes**: thank new sponsors by handle.
5. **Issue templates / Discussions**: occasional, polite mention that sponsorship keeps the project sustainable.

## 6-week traction plan

| Week | Action | Channel |
|---|---|---|
| 1 | Publish GitHub Sponsors profile with the content above; add badge + `docs/SPONSORS.md`. | Repo |
| 2 | Post a short “why I’m funding this with sponsors, not subscriptions” thread on the maintainer’s LinkedIn / X. | Social |
| 3 | Add a “Sponsor” callout to the next release notes. | Release notes |
| 4 | Reach out to 5 companies that use or could use ATSassin; offer a free logo placement in exchange for a $100+/mo sponsor tier. | Direct outreach |
| 5 | Pin a “How to support ATSassin” post in Discord and GitHub Discussions. | Community |
| 6 | Review sponsor conversion and adjust tier names, perks, or goals based on feedback. | Analytics |

## Traction tactics that work

- **Be specific about costs.** “CI minutes and release hardware” is more compelling than “support the project.”
- **Tell stories.** Share user testimonials, before/after impact, or contributor milestones.
- **Make the ask visible.** The README badge should be above the fold; the sponsor section should be easy to find.
- **Thank publicly and promptly.** Tag new sponsors in release notes and on social media (with permission).
- **Approach companies directly.** A single $100–$500/month company sponsor is often easier to land than 50 individual $5 sponsors.
- **Link from high-traffic pages.** README, release notes, documentation footer, and any public talks or posts.
